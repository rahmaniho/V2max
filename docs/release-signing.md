# انتشار امن و سازگاری به‌روزرسانی

نسخه‌های شاخه‌ها و درخواست‌های ادغام فقط برای آزمون ساخته می‌شوند و با کلید debug موقت امضا می‌شوند؛
این APKها **به‌روزرسانی قابل نصب روی نسخهٔ منتشرشده نیستند**. گردش کار این شاخه دیگر کلید انتشار را از
GitHub Actions cache بازیابی یا با رمز ثابت تولید نمی‌کند. برای push روی `main`، ساخت و انتشار فقط با
وجود چهار GitHub Actions secret زیر ادامه می‌یابد:

- `V2MAX_RELEASE_KEYSTORE_BASE64` — محتوای base64 مخزن کلید انتشار؛
- `V2MAX_RELEASE_STORE_PASSWORD`؛
- `V2MAX_RELEASE_KEY_ALIAS`؛
- `V2MAX_RELEASE_KEY_PASSWORD`.

این مقادیر باید فقط در تنظیمات امن GitHub و خارج از مخزن و گفتگو تنظیم شوند. پیش از انتشار، اسکریپت
`scripts/verify-release-signing.sh` گواهی همهٔ APKها را با APK رسمی v2.3.1، که هش فایلش در اسکریپت
ثابت شده، مقایسه می‌کند. در نبود secrets، ناسازگاری امضا یا خطای ساخت، انتشار متوقف می‌شود؛ کلید جدید
به‌صورت خودکار جایگزین کلید نسخه‌های نصب‌شده نمی‌شود. استفاده از کلید متفاوت بدون برنامهٔ مهاجرت به
معنی ناممکن شدن به‌روزرسانی روی نصب‌های فعلی است.

## بررسی لازم پیش از انتشار

گردش کار قبلی یک keystore با رمز ثابت را در Actions cache نگهداری می‌کرد. وجود آن cache روی `main`
مشاهده شده است؛ cache سازوکار نگهداری امن secrets نیست و ممکن است برای workflowهای دیگرِ مجاز به
خواندن cache قابل دسترسی بوده باشد. این موضوع به‌تنهایی اثبات دسترسی غیرمجاز نیست، اما کلید باید
احتمالاً در معرض دسترسی تلقی و توسط مالک مخزن بررسی شود. تغییر این شاخه cache یا گردش کار `main` را
تا زمان ادغام تغییر نمی‌دهد. پیش از پاک‌کردن cache، باید مطمئن شد تنها نسخهٔ کلید فعلی از دست نمی‌رود.
انتقال کلید به secrets، ارزیابی رخداد، و در صورت لزوم برنامه‌ریزی چرخش امضا با حفظ مسیر مهاجرت کاربران
بر عهدهٔ مالک است. تطبیق گواهی فقط سازگاری را می‌سنجد و امن‌بودن کلید قبلی را اثبات نمی‌کند.

# انتشار امن و سازگاری به‌روزرسانی

نسخه‌های شاخه‌ها و درخواست‌های ادغام فقط برای آزمون ساخته می‌شوند و با کلید debug موقت امضا می‌شوند؛
این APKها **به‌روزرسانی قابل نصب روی نسخهٔ منتشرشده نیستند**. گردش کار این شاخه دیگر کلید انتشار را از
GitHub Actions cache بازیابی یا با رمز ثابت تولید نمی‌کند. انتشار به‌صورت پیش‌فرض غیرفعال است و صرفِ
push یا ادغام روی `main` انتشار را شروع نمی‌کند. فقط پس از بررسی امنیت کلید توسط مالک، با تنظیم متغیر
مخزن `V2MAX_RELEASE_APPROVED` به مقدار `true`، وجود چهار GitHub Actions secret زیر و اجرای دستی گردش
کار روی `main` با گزینهٔ `publish_release=true` می‌توان فرایند انتشار را آغاز کرد:

- `V2MAX_RELEASE_KEYSTORE_BASE64` — محتوای base64 مخزن کلید انتشار؛
- `V2MAX_RELEASE_STORE_PASSWORD`؛
- `V2MAX_RELEASE_KEY_ALIAS`؛
- `V2MAX_RELEASE_KEY_PASSWORD`.

این مقادیر باید فقط در تنظیمات امن GitHub و خارج از مخزن و گفتگو تنظیم شوند. ساخت، Gradle و آزمون‌ها
همیشه بدون کلید انتشار اجرا می‌شوند. فقط پس از موفقیت ساخت و آزمون‌های امنیتی Android 24، 30 و 35،
یک job جدا با دسترسی صرفاً خواندن، همان APKهای آزمایش‌شده را دوباره امضا می‌کند؛ محتوای غیرامضایی و
تراز APKها تطبیق داده می‌شود. اسکریپت `scripts/verify-release-signing.sh` گواهی همهٔ APKها را با APK
رسمی v2.3.1، که هش فایلش در اسکریپت ثابت شده، مقایسه می‌کند. job انتشار دسترسی نوشتن دارد اما کلید
خصوصی را دریافت نمی‌کند. نام بسته و هر دو شمارهٔ نسخه نیز با آخرین APK منتشرشده مقایسه می‌شوند.

انتشار فقط در تگ شماره‌دار جدید و پس از بارگذاری و تأیید هش هر چهار فایل روی پیش‌نویس انجام می‌شود؛
تگ یا asset موجود بازنویسی نمی‌شود. `apk-latest` قدیمی دیگر بازنویسی نمی‌شود و ممکن است قدیمی بماند؛
برای دریافت نسخه از صفحهٔ Releases یا `releases/latest` استفاده کنید. اگر کار پس از ساخت تگ یا
پیش‌نویس متوقف شد، انتشار خودکار بازنویسی نمی‌کند: مالک باید وضعیت تگ، پیش‌نویس و فایل‌ها را بررسی کند
و برای تلاش مجدد تصمیم بگیرد.

تا وقتی اجرای دستی صریح و متغیر تأیید هر دو فراهم نباشند، حتی `main` فقط APK آزمایشی می‌سازد و
انتشاری انجام نمی‌دهد. گزینهٔ `security_only` با انتشار هم‌زمان قابل استفاده نیست. در نبود secrets،
ناسازگاری امضا، تکراری‌بودن نسخه یا خطای ساخت/آزمون، انتشار متوقف می‌شود؛ کلید جدید
به‌صورت خودکار جایگزین کلید نسخه‌های نصب‌شده نمی‌شود. استفاده از کلید متفاوت بدون برنامهٔ مهاجرت به
معنی ناممکن شدن به‌روزرسانی روی نصب‌های فعلی است. آزمون ارتقای debug جای آزمایش ارتقای APK رسمی روی
دستگاه واقعی را نمی‌گیرد.

## بررسی لازم پیش از انتشار

گردش کار قبلی یک keystore با رمز ثابت را در Actions cache نگهداری می‌کرد. وجود آن cache روی `main`
مشاهده شده است؛ cache سازوکار نگهداری امن secrets نیست و ممکن است برای workflowهای دیگرِ مجاز به
خواندن cache قابل دسترسی بوده باشد. این موضوع به‌تنهایی اثبات دسترسی غیرمجاز نیست، اما کلید باید
احتمالاً در معرض دسترسی تلقی و توسط مالک مخزن بررسی شود. تغییر این شاخه cache یا گردش کار `main` را
تا زمان ادغام تغییر نمی‌دهد. پیش از پاک‌کردن cache، باید مطمئن شد تنها نسخهٔ کلید فعلی از دست نمی‌رود.
انتقال کلید به secrets، ارزیابی رخداد، و در صورت لزوم برنامه‌ریزی چرخش امضا با حفظ مسیر مهاجرت کاربران
بر عهدهٔ مالک است. تطبیق گواهی فقط سازگاری را می‌سنجد و امن‌بودن کلید قبلی را اثبات نمی‌کند.
